# 0002 搜索不遵循 .gitignore

Status: accepted
Date: 2026-11-19

## 背景

多仓库工作区常见的组织方式是「外层根仓库 + 多个子仓库」，根目录的 `.gitignore` 通常会用 `/*` 忽略所有子目录，再由各子仓库自行管理版本。如果插件遵循 `.gitignore`，用户期望的 JetBrains 风格全局搜索就会完全漏掉子仓库源码。

## 决策

文件内容搜索与文件名列举统一传入 `--no-ignore-vcs`，不遵循 `.gitignore`；改用显式维护的 `SKIP_DIR_NAMES` 跳过依赖目录、VCS 内部目录、构建产物、虚拟环境和常见缓存目录。ripgrep 与 Node 回退遍历共用同一份排除列表。

## 影响

- 多仓库工作区下的子仓库源码可以被正常搜到，符合全局搜索的直觉预期。
- 被 `.gitignore` 忽略但仍存在于磁盘的生成文件可能会出现在结果中，必要时通过扩充 `SKIP_DIR_NAMES` 处理。
- 两套引擎的排除规则必须从同一来源派生，防止 ripgrep 与回退遍历表现不一致。
- `.gitignore` 不再承担「屏蔽某目录搜索」的作用，需在用户文档中明确说明。

## 备选方案

- **遵循 `.gitignore`**：在多仓库工作区下会漏搜所有子仓库，放弃。
- **只排除 `node_modules` 和 `.git`**：构建产物、Python 虚拟环境和各类缓存仍会污染结果并拖慢检索，放弃。
- **开放自定义排除表配置**：当前没有配套配置界面，会增加状态与迁移成本；先采用固定排除表，等有明确需求再评估。
